# 七类可引用资源

前四类是「素材」，第五类是「组织」，第七类是「内容外置」：

1. **K3s 集群**：在哪里跑（kubeconfig + context + namespace）。
2. **Harbor 镜像仓库**：Worker 镜像从哪来。合同要求**单仓库存全部四类 Harness 镜像**、按标签前缀识别（`claudecode-ox_v1` / `codex-ox_v1` / `opencode-ox_v1` / `dsh-ox_v1`）；测试通过即自动同步四个 Harness 模板。
3. **Gitea**：任务分支与交付仓库所在的 Git 服务（按项目 remote 自动匹配）。
4. **Harness 模板**：一个模板 = 某种开发工具的 Worker 形态（镜像 digest 钉死 + CPU/内存规格），**不绑模型**。
5. **模型连接**：可用的模型服务（协议 + URL + 凭证 ref + 模型 ID）。与 Harness 独立，运行时按协议配对。
6. **执行资源池**：`池 = 集群 × 允许的 Harness 白名单 × 并发总量`。**并发是池级总量**——不分 Harness、所有使用该池的项目共享，超出自动排队而非失败。
7. **对象存储（artifact store）**：大内容外置的 S3 兼容存储（endpoint + bucket + path-style + 凭证 ref）。项目可绑定一个存储，worker 与宿主把超长内容外置为 `artifactRef` 地址，有界通道只传地址与摘要。

## 引用关系

- 池 → 集群 + 镜像仓库 + 模板白名单
- Agent 组合 → 池 + 模板 + 模型连接
- 项目 → （可选）对象存储

**删除被引用的资源失败关闭**，并列出引用者。

## 生效时机（容易被误判为缺陷）

- **诊断面**——可用性探针、只读发现、删除影响——读**当前已保存**配置，保存即可测。
- **运行时面**——池、K3s client、派发准入——**重启 Profile 后生效**。保存新池后，正在运行的宿主派发行为不变，重启才接入。

保存后立刻发现「派发还在用旧池」不是缺陷，是这条边界。
