# 本地执行与失败候选恢复

## 本地派发的环境形态

本地 Git 派发会准备一个**自足的任务仓库**，并在启动 Worker 前检查其真实的原生沙箱。

Maven 使用任务 `.git` 目录下的**私有仓库缓存**；共享的 `~/.m2` **不会**被置为可写。

## 上一次失败留有改动时

调用 `pactflow_local_recovery_candidates`。

- `available=false` 是一个**显式的不可用候选**，不是「没有候选」。照实报告，不要当作可以忽略。
- 只读地比对符合条件的候选，**只选一个**。
- 在新的已确认方案里，把 `recovery:{runId,digest}` 放进该节点的 git 执行路由，并把相同的 `recovery_run_id` / `recovery_digest` 传给派发。
- Worker 必须**审查并验证**所选的未提交输入，然后产出一个**新的提交**。

## 绝对不要做的四件事

1. **静默合并两个候选**——那会造出一份谁都没审过的混合改动。
2. **把历史失败 Run 改成成功**——失败记录是证据，不是待修复的状态。
3. **删除保留现场**——保留策略只标记不删除，删除是所有者的裁决。
4. **仅仅切换 spawn/fork 就重试同一个环境失败**——换执行器不解决环境问题，只会再失败一次并多留一份现场。
