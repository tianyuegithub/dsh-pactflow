# 运行态异常速查

| 现象 | 含义 | 处置 |
|---|---|---|
| 节点显示「已暂停（等待决策）」 | 重试预算耗尽 | 人显式恢复（`resumeNode`）——不要靠重复派发绕过 |
| 任务排队不动 | 池槽被占满（跨项目共享） | 等待 / 调池并发并重启 Profile / 换池 |
| 收口被阻断 | 门禁证据缺失（逐项指名）或宿主基线失败 | 补验证 / 检查基线命令输出；**不要削弱门禁** |
| 收口停在「等待外部评审」 | 受保护分支要求批准或 CI 检查 | 等评审者批准或 CI 通过；**不要建议手工去网页合并** |
| Worker 镜像拉取失败 | pull secret 或镜像 digest 不符 | 核对池的拉取密钥与模板 digest |
| 保存新池后派发行为没变 | 运行时面重启才生效（非缺陷） | 重启 Profile |
| 节点标「输入已过期」 | 上游重跑产生了新提交 | 由人判断是否需要重跑该节点；系统不会自动级联 |

## 通用原则

- **区分「缺少证据」与「证据表明不存在」**。查不到不等于没有。
- **失败关闭优先**。判定不了就拒绝并指名原因，不要放行。
- **不要用重试掩盖诊断**。同一错误重复三次仍不变，说明缺的是理解不是次数。
- 报告阻塞用 `pactflow_block_autopilot`，写清具体缺什么，而不是笼统的「失败了」。
