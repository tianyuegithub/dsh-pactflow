# validation-policy (delta)

## ADDED Requirements

### Requirement: 人登记的最小验证策略必须由宿主在收口时强制

用户 SHALL 能登记最小验证策略：一个或多个「要求组」，每组声明必须成功执行的验证配置档（profile）集合与生效范围（建议：每工作区默认，可按需求覆盖）。宿主在收口时 SHALL 检查该需求全部交付构件在**确定候选提交**上的验证证据——要求组内的每个 profile 都必须确有成功执行证据，任一缺失即失败关闭并**逐项列出缺失的 profile**。策略 MUST 由人经客户端配置写入；Agent 工具 MUST NOT 暴露策略的读取或修改接口；策略 MUST NOT 能被任务侧配置省略或降低。

#### Scenario: 满足策略时收口正常

- **WHEN** 需求的全部交付构件在候选提交上对策略要求组内每个 profile 都有成功执行证据
- **THEN** 收口按既有流程继续，不因策略增加额外延迟或副作用

#### Scenario: 缺失要求的验证时失败关闭

- **WHEN** 某要求组内的 profile 在候选提交上没有成功执行证据
- **THEN** 收口失败关闭，错误逐项列出缺失的 profile 名称

#### Scenario: 未配置策略时行为不变

- **WHEN** 工作区与需求都没有登记任何策略
- **THEN** 收口行为与现状完全一致

#### Scenario: 模型不可触及策略

- **WHEN** 枚举 Agent 面全部 PactFlow 工具
- **THEN** 不存在任何能读取或修改验证策略的工具；策略仅经客户端配置路径写入
