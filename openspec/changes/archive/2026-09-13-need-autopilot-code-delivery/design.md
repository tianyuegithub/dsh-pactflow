## Context

目标及非目标见 proposal.md。复用已实现的人工执行方案选择、十阶段门禁、任务运行、验证和代码收口。原生 Agent 支持插件来源的 followup、状态事件和冷会话恢复；已有恢复只覆盖运行和清理，需补充挂机控制。

## Decisions

- 客户端原生浮层增加按需求挂机控制。启动和控制仅经用户接口，模型仅可读取状态及报告阻塞。每个会话同时一个活动挂机需求，避免不同需求争抢同一编排器。
- 新增生产者 0.4.0 与 `pactflow/autopilot-updated` 事件；控制记录并入既有 delivery 投影的可选 map，不创建第二份任务/阶段体系。授权 id、修订、作用域摘要、预算、推进计数和原因持久化；旧生产者保留只读。
- 自动评审 source 为 `autopilot-policy`，绑定授权 id、需求/方案/交付摘要；只由宿主依据有效授权生成。人工路径继续使用原生 approval。自动验收复用实际 Git 结果与宿主验证策略，不能用说明文字替代。
- 推进器由 ctx.effect 管理一个有界周期与事件唤醒，按会话串行。发消息前持久化唤醒标识及次数，消息使用插件来源。内存去重覆盖同进程交接；重启时查持久消息标识与实际执行状态，不盲目重发写操作。
- 首次默认预算作为可编辑建议：4 小时、60 次编排模型调用、10 次执行、最大并发 1；客户端和宿主都有范围校验，原有每节点重试上限仍生效。简单真实交付实测已用 21 次编排调用，因此建议 60 次留出复验空间；启动前用户仍显式确认，可修改。没有可靠计费源，不提供虚假金额硬上限。
- 暂停只停止后续调度；停止/超时取消当前编排轮与可取消执行。用户新消息触发暂停，用户明确恢复才继续。无进展按阶段、节点终态、成功提交与验证事实衡量，不能靠反复写评审记录刷新进展。
- 挂机不扩大目录写权限；不自动批准文件/命令安全请求，不改变 Full access 等原生权限档。权限不足进入阻塞。
- 旧运行继续对账；活动挂机需求加入冷会话发现，即便暂时没有 Run 也恢复。环境摘要变化后暂停，旧版本不能读取新事件时拒绝回退启动，不能伪称等价回滚。
- 授权资源优先使用项目已配置的集群执行规格；无集群时使用已注册本地执行器并显式绑定进程内身份。本地冷重启后需重新授权，集群相同配置可继续；编排模型调用预算不包含不可观测的远端执行器模型细分调用。
- 收口在实际推送前持久化精确集成分支/提交/工作树身份并刷新到磁盘；推送、创建和合并请求前重核授权与取消信号。验证子进程与 Git 推送接收取消信号。远端结果未知时保留收口责任，恢复先查已有合并，不能假称已撤回。

## Alternatives and review

纯提示词无法证明模型结束后继续推进；模拟点击审批会伪造人工授权；独立常驻编排服务增加重复 owner。采用宿主插件推进器与明确策略授权。架构判断：有条件支持，进入运行更新前须证明取消/越权/预算/无进展/恢复与真实交付路径。

## Ownership and validation

本 change 单写 `need-autopilot`；依赖的人工模式规格仍由原 change 持有并保持原验收。新增控制 UI 文件可独立实现，宿主、事件、工具和运行整合由主控持有。测试分离纯决策、宿主信任边界、原生浏览器和真实模型；临时环境验证不写客户仓库或部署生产。
