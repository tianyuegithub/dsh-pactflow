## Why

真实本地执行两次因共享工作树的 Git 元数据位于沙箱外而不能提交；构建缓存也越过了任务目录边界。现有临时目录验收漏测了主仓位于普通代码目录的情况。

## What Changes

- 新本地运行使用包含独立 Git 元数据的任务仓库，保留既有远程分支同步和验收合同；集群运行及历史工作树不迁移。
- 派发前执行同策略的真实文件/Git/必要工具检查，失败不启动业务执行代理。
- Maven 使用任务内私有缓存，完整共享 `~/.m2` 授权已获用户同意，但因当前宿主无精确附加目录能力暂缓，禁止宿主私有补丁或扩大整个用户目录权限。
- 提供失败候选的只读摘要与显式恢复输入；源摘要参与执行方案授权，新运行只采用一份冻结候选，旧运行与现场保留。
- **BREAKING** 新运行规格由新版事件生产者登记，旧版不得剥离新字段后误按共享工作树解释；历史事件仍可读取。

## Capabilities

### New Capabilities
- `local-execution-workspace`: 本地仓库隔离、环境预检、任务缓存和有来源证明的候选恢复。

### Modified Capabilities
无。统一准入、执行方案精确授权和 Git 收口合同继续沿用。

## Impact

涉及 Host（宿主）的 Git 工作区/派发/清理、Agent（智能体）工具、Remote（远程调用）候选查询和 Session Event（会话事件）运行规格；增加原生沙箱服务的可选依赖。与目标架构的隔离执行、真实验收及可恢复现场对应。非目标：直接代写业务、合并两份候选、自动成功、共享主仓 Git 写权限、改动宿主源码、全局权限扩大、集群镜像或发布拓扑变更。
