## Purpose

让任务依赖不仅决定执行顺序，也决定**成果输入**：声明为代码输入的依赖，其精确成功提交必须成为后序任务的不可变执行基线；同时保证集成的任务集合核验按依赖闭包判定，既接受「后序历史已包含前序成果」的合法依赖链，又继续拒绝任何未授权提交。

## ADDED Requirements

### Requirement: 代码输入依赖必须成为后序任务的执行基线

节点 SHALL 可声明 `codeInputs`（必须是其已声明依赖的子集）。派发该节点时，Host SHALL 把每个代码输入依赖**最新成功 Run 的精确提交**纳入该 Run 的执行基线，并在工作树中按精确提交取回与合并后再让 Worker 施工。基线 MUST 以精确提交表达，MUST NOT 依赖可移动的分支引用。

#### Scenario: 后序任务能看到前序成果

- **WHEN** A 成功提交一个文件，B 声明 A 为其代码输入并随后派发
- **THEN** B 的工作树基线包含 A 的该提交，B 不因缺少前序文件而失败

#### Scenario: 代码输入必须是已声明的依赖

- **WHEN** 某节点把非依赖节点声明为代码输入
- **THEN** 创建节点被拒绝

#### Scenario: 前序提交不可获取时失败关闭

- **WHEN** 某个代码输入依赖的精确提交无法取回，或与任务基线冲突
- **THEN** 派发在该节点上失败关闭并给出原因，不静默忽略该输入

### Requirement: 集成任务集合按依赖闭包核验

收口集成时，Host SHALL 按依赖闭包核验任务集合：每个预期任务提交 MUST 是集成提交的祖先；集成提交引入的每个提交 MUST 落在预期提交的祖先闭包内（或以首父合并提交的形态存在）；首父合并的额外父 MUST 是预期提交之一。任何既不属预期提交祖先闭包、也非合法合并形态的提交 MUST 导致拒绝。

#### Scenario: 合法依赖链被接受

- **WHEN** B 的提交历史已包含 A 的提交，且两者都是预期任务
- **THEN** 集成核验通过

#### Scenario: 未授权提交被拒绝

- **WHEN** 集成分支除预期任务外还合并了一个未预期提交
- **THEN** 集成核验失败关闭

#### Scenario: 独立多任务仍被接受

- **WHEN** 多个互不依赖的预期任务各自合并进集成分支
- **THEN** 集成核验通过
