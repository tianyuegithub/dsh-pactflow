## Context
目标及非目标见 proposal。既有宿主位于本机回环地址，Pod 不挂载集群服务账号；现有 DSH 具有 approval/request 和 user-questions/request 扩展点。原镜像 runner 构建源在本仓库缺失，新增独立镜像构建入口，不依赖 Hermes。

## Decisions
- 架构结论：有条件支持。用户已确认官方宿主插件与可定制执行器分离；进入交付须通过真实容器、页面、取消与断线验收。保留当前工作区唯一写 owner，复用前序未提交实现，不另开缺少这些依赖的源码副本。
- 传输复用已认证 Kubernetes exec 双向流；宿主固定执行只读挂载的连接脚本，该脚本转发容器本地 Unix socket。无额外公网端口/服务账号；拒绝工作流反向调用宿主 API 的通用能力。宿主前后核对精确 Pod/Job 身份。
- 执行器插件运行在容器 DSH 根代理，注册两种交互处理器。保留 approval policy=never 的原生拒绝语义；宿主不伪造 Agent、不绕过子代理交互守卫。
- 协议 dsh-worker-interactions/v1 使用有界 JSON 行。请求绑定启动实例 bootId、requestId、类型及摘要；宿主添加 session/need/run/podUID。只允许一个未处理请求/执行尝试，最多 32 个请求，单条最多 64KiB，单次等待最多 15 分钟且不延长作业总时限。
- 宿主控制记录为现有会话 delivery 投影的可选 workerInteractions 映射，新增 0.5.0 生产者并保留旧版本只读。状态 pending→answered→delivered；pending/answered 可因超时、任务终止、实例变化转 expired/cancelled。用户决定先 flush，再发送，收讫单独落账。
- 用户答复仅来自 Remote 控制面；审批只能一次批准/拒绝，问题核对合法选项、数量与文本长度；allowCustom 明确表示其它文本是否允许，原生 DSH 问题保留其可自定义语义，封闭题设为 false。宿主另持有不可变 expiresAt=min(接收时间+15分钟, 作业固定期限, 适用挂机期限, 执行器声明期限)，不信任远程时钟延长等待。等待时作业保持运行，页面交互区显示待人工处理；挂机不替用户批准未授权操作。
- 同进程连接丢失保存待决请求和原 Promise，重连重发相同请求；宿主重放已决定记录。进程实例改变则旧请求失效，不能推断旧调用已恢复。取消关闭桥接，拒绝迟到答案。
- 新模板字段 interactionProtocol 显式启用，且只有 dsh 可用；旧模板缺省关闭。镜像内 runtime manifest 与握手证明协议版本。版本/镜像固定，不把所有主线更新作为升级前置。
- 答案必须使用宿主 Ed25519 私钥签名，私钥由现有凭证服务持有，Pod 只得到只读公钥。签名绑定 runId、podUid、bootId、requestId、摘要、答案与期限，防止同 UID 模型自行连接套接字伪造同意；公钥绑定不可变作业规格。签名私钥变更后旧运行拒绝发送答案，不猜测等价身份。
- 宿主拥有协议、事件、Kubernetes 接线与验收；独立实现代理只拥有新的客户端交互组件。安全决策和共享入口由主控写入。

## Risks / Trade-offs
- exec 通道断开 → 重连及已落账答案重送，不把传输错误当同意；权限不足明确不可用。
- 任意 shell 交互不经过原生扩展点 → 非目标，仍靠非交互配置与有界超时。
- 执行器可提出恶意问题 → 内容视为不可信，转义显示、限长、已知凭证脱敏；不授予跨任务权限。
- 旧插件不能读新事件 → 降级前保留新版本及日志，不承诺直接回滚。

## 已验证实现边界

首个固定基础镜像的 DSH 版本为 0.1.1-rc.2，原生提问接口为 registerProvider，因此镜像清单明确配置 provider-v1。较新 SDK 的事件式接口为 waterfall-v1，代码显式区分但尚未对对应镜像做实际验收。此次不修改 DSH 核心，使用插件命名导出的 apply/inject/Config；真实容器检查发现默认函数导出会遗漏依赖声明，修复后原生审批与提问通过。

实际集群测试覆盖 3 次交互、连接进程中断后的同请求重连、浏览器重载、停止后迟到批准拒绝与真实任务分支提交。宿主会话恢复以真实 JSONL 落盘、新 Context 重放和同启动实例重送验证；未执行操作系统级宿主崩溃的整链测试。分发镜像没有验收钩子，单独的验收变体仅用于测试。镜像映射由随包 release-manifest.json 持有。
