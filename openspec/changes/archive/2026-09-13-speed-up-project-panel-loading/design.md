## Context

见 proposal.md。现有聚合接口的全量会话发现仅供迁移候选使用，却成为首屏前置。客户端已有请求顺序门禁与草稿管理，需沿用。

## Goals / Non-Goals

按已确认范围拆分只读加载；不改宿主、不改会话事件或写接口。旧聚合接口继续存在，避免外部调用者兼容风险。

## Decisions

- 新增轻量工作区目录、单工作区详情、单工作区迁移候选三个只读接口。目录直接来自宿主注册表；详情读取单份配置和单仓库事实；候选只访问工作区注册的会话编号。
- 客户端目录、资源目录独立发布结果。详情绑定选中编号，切换立即停止显示旧详情，独立门禁阻止迟到响应。迁移查询由按钮触发，不自动展开全量日志。
- 不采用简单全量缓存：缓存不能消除首次开销，且增加配置过期风险。不修改原聚合接口返回结构：保持兼容更安全。
- 错误状态独立持有，重试只请求失败层；写成功后刷新列表、资源目录与当前详情。保持原有修订校验及草稿管理。

## Risks / Trade-offs

- 单个大仓库详情仍可能慢 → 只影响当前详情，导航可用。
- 当前工作区历史会话仍可能多 → 用户显式查询候选才支付读取成本，错误不吞掉。
- 响应顺序与保存刷新可能交错 → 按代际失效、编号匹配，回归测试覆盖。

## Migration Plan

无需数据迁移。构建和测试通过后更新用户提供的本地开发宿主插件并验证；保持可恢复安装产物，不修改 DSH 源码。回退插件包即可恢复旧界面。规格归档与 Git 提交推送不属于本次修复授权。
