# release-gate-prerequisite-coverage (delta)

## MODIFIED Requirements

### Requirement: 发布门禁的前置检查必须被测试覆盖

发布门禁脚本的前置检查（决定一次运行是否「武装」）SHALL 被测试覆盖其**确定性分支**——即不依赖真实集群/凭据、可离线判定的部分。前置检查 MUST NOT 在无任何测试的情况下决定「拦住合法运行」或「放行未武装的运行」。

此外，门禁的**武装集** SHALL 覆盖每一个被发现的 e2e 套件所依赖的环境开关；门禁 SHALL 把其检查过的凭据解析值**注入被测子进程的环境**，而不是仅验证其存在。若某套件的开关缺失或凭据未注入，该套件将静默跳过或在其 `beforeAll` 失败，使「零跳过」通过条件结构上不可满足——该不可满足性 MUST 由离线测试暴露，而不是只在真实运行时才发现。

#### Scenario: 未武装时报告缺失前置

- **WHEN** 门禁要求的开关（如 `DSH_SNAPSHOT=record`）未被设置（空或其它值）
- **THEN** 前置检查的缺失清单包含该开关对应的条目

#### Scenario: 已武装时不再报告该前置

- **WHEN** 该开关已按要求设置
- **THEN** 缺失清单不再包含该条目，且返回值恒为非空字符串数组

#### Scenario: 前置检查被破坏时测试失败

- **WHEN** 该确定性分支被错误地短路或删除
- **THEN** 对应测试失败，而不是静默放行

#### Scenario: 武装集覆盖每个门控套件的开关

- **WHEN** 任一 e2e 套件以其模块级开关（如 `DSH_REAL_APPROVAL`）决定是否跳过
- **THEN** 门禁的武装集包含该开关，且从一个套件源码反推出的所有必需开关都被覆盖

#### Scenario: 新增门控套件未纳入武装集时测试失败

- **WHEN** 新增一个被环境开关门控的 e2e 套件，但未把其开关加入武装集
- **THEN** 反推必需开关的离线测试失败，而不是让该套件静默跳过而门禁永不可通过

#### Scenario: 检查到的凭据被注入被测子进程

- **WHEN** 门禁在前置检查中解析了真实套件所需的凭据（如 `DEEPSEEK_API_KEY`）
- **THEN** 同一解析值被注入门禁启动的子进程环境，使 record 模式套件不会因缺少凭据而在 `beforeAll` 失败（被计为跳过）

#### Scenario: 缺失凭据时以可诊断清单失败关闭

- **WHEN** 门禁所需的凭据既不在启动环境也不在凭据库中
- **THEN** 门禁在运行真实套件之前失败关闭，并列出具体缺失的凭据名，而不是让套件跳过后再以「零跳过」计数拒绝
