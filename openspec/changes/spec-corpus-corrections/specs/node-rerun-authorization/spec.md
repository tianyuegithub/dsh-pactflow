# node-rerun-authorization (delta)

## REMOVED Requirements

### Requirement: 重跑必须复用既有预算与暂停语义

整条被替换，理由见下方新增的同主题 Requirement。此处不是放宽——预算仍然有界、拒绝仍然显式且可预见；被移除的只是「上限耗尽时把节点写成 `paused`」这一处置方式，以及与之绑定的 Scenario「上限耗尽进入持久暂停」。

## ADDED Requirements

### Requirement: 重跑必须复用既有预算且拒绝时不得改动任何状态

重跑 SHALL 消耗运行预算并按既有 attempt 上限合同计数，MUST NOT 另设第二套上限。

上限耗尽时，重跑 SHALL 被**拒绝**并指名实际尝试数与预算值，且该节点的状态、修订及其全部 Run MUST NOT 被改变。该拒绝 SHALL 在预览入口先行可见，使调用者在请求之前就能知道它会被拒绝。

> 被本条替换的旧表述要求「上限耗尽时 SHALL 进入既有的持久 `paused` 状态，MUST NOT 以重复抛错表达」。那在这里不成立，且实施它会造成不可逆损坏：重跑的前态是 `succeeded`，把 `paused` 写上去等于**为了拒绝一次操作而摧毁交付终态**，而没有任何路径能把 `succeeded` 放回去——该需求从此永久无法收口。`retryNode` 可以这样做，是因为它的前态是 `failed`，改成 `paused` 无损。两者形似而前态不同，旧表述把前者的写法照搬到了后者。该缺陷已由评审抓出并修复；本条是把修复回写进正文。
>
> 旧表述真正要防的是「拒绝只以异常表达、用户看不到也查不到」。这一点被完整保留并加强：拒绝必须指名实际尝试数与预算值，且必须在预览入口先行可见。

#### Scenario: 重跑计入 attempt 上限

- **WHEN** 节点历史 attempt 已接近上限，重跑被授权
- **THEN** 新 attempt 计入同一上限判定，不另起计数

#### Scenario: 上限耗尽时拒绝且不改动任何状态

- **WHEN** 重跑会使 attempt 超出上限
- **THEN** 重跑被拒绝并指名实际尝试数与预算值；该节点的状态、修订与其全部 Run 均不发生任何改变

#### Scenario: 预览先行告知该拒绝

- **WHEN** 在请求重跑之前查询该节点的重跑预览
- **THEN** 预览已包含该预算拒绝的原因，调用者无需先触发一次失败才能知道
