# artifact-ref-handoff 变更增量

## Purpose

使多 worker 与调度之间的大内容（计划、报告、日志、诊断）经外部对象存储以结构化地址（artifactRef）传递：插件可强制的有界通道只承载地址与摘要，超长内联被门禁拒绝，消费者先解析后执行，从而消除截断破坏交付原子性的问题。

## ADDED Requirements

### Requirement: 大内容必须外置并通过门禁强制

在插件拥有的有界通道上，内容超过该通道配置阈值时，生产者 MUST 将其外置为 artifactRef，通道只承载 ref 与不超过限额的摘要。有界通道收到超过阈值且未外置的内联载荷时，门禁 MUST 以显式错误码 `pactflow.artifact.oversize` 拒绝该载荷并指引走 artifact 路径；MUST NOT 静默截断或静默放行。

阈值 SHALL 按通道配置，且 MUST NOT 大于该通道自身的硬限——包括结果文档通道（其硬限为容器终止消息上限，阈值 MUST 显著低于该上限以容纳文档其余字段）。

本要求只覆盖插件可拦截的通道：进入执行输入、结果文档、桥载荷、会话事件与交互请求的载荷，以及插件自身的读取降级路径。模型在会话正文中的直接输出不属于插件可拦截通道，MUST NOT 被声称受本门禁覆盖。

#### Scenario: 超限内联被拒

- **WHEN** 任一插件可强制的有界通道收到超过该通道阈值的内联载荷
- **THEN** 该载荷被拒绝并返回 `pactflow.artifact.oversize` 与外置指引，不产生部分生效的内容

#### Scenario: 外置后通过

- **WHEN** 同样的内容先上传对象存储、通道内只传 artifactRef 与限额内摘要
- **THEN** 门禁放行，接收方可凭 ref 获取全量内容

#### Scenario: 阈值不超过通道硬限

- **WHEN** 枚举各通道配置的阈值与其硬限
- **THEN** 每个阈值都不大于对应通道的硬限，结果文档通道的阈值显著低于其终止消息硬限

#### Scenario: 不可拦截通道不被声称覆盖

- **WHEN** 核对本能力的覆盖声明与各通道执行点
- **THEN** 模型在会话正文中的直接输出被明确列为覆盖边界之外，不作为门禁成效宣称

### Requirement: 结构化地址合同零签名且不可变

artifactRef MUST 为结构化字段并至少包含存储定位（bucket/key）、etag、字节数与内容 hash，并包含 `kind` 与不超过限额的摘要（摘要 MUST 同时受行数与字节数约束）。ref MUST NOT 携带签名或任何凭据；预签名 URL 视同凭据，MUST NOT 进入 Session Event、Remote payload、对话内容或持久日志。

后端返回版本标识时，ref MUST 记录该版本标识且 MUST NOT 在缺失时静默省略为等价物；消费侧解析按该版本标识取对象，版本标识存在而对象版本不可得时 MUST 显式失败。ref 对应的对象一经写入确认，发送方 MUST NOT 修改或删除该对象；删除只能由保留策略执行。

对象 key SHALL 包含不可预测的随机段，使并发或其他运行无法以可预测名称覆写既有对象；写入前发现同一 key 已存在时 MUST 拒绝该次写入并显式报错，MUST NOT 静默覆盖既有对象。

#### Scenario: 带签名地址被拒

- **WHEN** 通道载荷中的地址携带预签名或内嵌凭据
- **THEN** 该载荷被门禁拒绝，并按凭证红线处置，不进入事件流

#### Scenario: 零签名地址通过

- **WHEN** 载荷携带仅含定位、版本与校验字段的 ref
- **THEN** 消费者可用自身凭据解析该对象

#### Scenario: 已确认对象不可被覆写

- **WHEN** 同一 key 被第二次写入，或引用指向已登记对象
- **THEN** 既有对象不被覆盖，第二次写入不产生对既有 ref 的替换（无静默版本漂移）

### Requirement: 消费者必须先解析再执行且失败显式

消费者遇到 artifactRef 时，MUST 先解析对象并校验 hash 与字节数，然后才能继续依赖该内容的执行。解析 MUST 只允许针对当前已绑定存储的目标；ref 指向绑定之外的目标时 MUST 拒绝。解析不存在、版本不符、hash 不符或字节数不符 MUST 产生显式失败并携带错误码，MUST NOT 以对话、会话记忆或推测内容替代对象内容。发送方 MUST 在对象存储确认写入（返回 etag，及后端提供的版本标识）之后才允许发出 ref。

#### Scenario: 对象缺失时失败关闭

- **WHEN** 消费者按 ref 解析对象但对象或版本不存在
- **THEN** 消费流程以显式错误终止并请求重发，不使用任何替代来源的内容继续执行

#### Scenario: 越出绑定的目标被拒

- **WHEN** ref 指向当前绑定之外的存储目标
- **THEN** 解析在发出请求前失败关闭，宿主不成为任意地址的取回通道

#### Scenario: 先发址后被拒

- **WHEN** 发送方在对象存储确认写入之前发出 ref
- **THEN** 该 ref 无法通过校验（缺少写入确认返回的 etag，或缺少后端已提供却未记录的版本标识），门禁拒绝其进入通道

#### Scenario: 内容损坏

- **WHEN** 解析得到的字节数或 hash 与 ref 不符
- **THEN** 该内容按损坏处理，消费流程显式失败，不降级使用

### Requirement: 上传前必须通过内容脱敏门

内容上传前 MUST 经过原始凭证扫描；命中凭证的内容 MUST 被拒收并报告脱敏失败，MUST NOT 写入对象存储。扫描 MUST 至少覆盖宿主已知绑定的凭据值与通用凭证形式；扫描器自身故障时 MUST 拒绝上传（fail-closed），MUST NOT 放行。对象存储按持久存储同等适用凭证红线。

#### Scenario: 含凭证内容被拒收

- **WHEN** 待上传内容包含原始凭证
- **THEN** 上传被拒绝并给出脱敏失败原因，对象存储中不产生该对象

#### Scenario: 扫描器故障时拒绝上传

- **WHEN** 脱敏扫描本身失败或不可用
- **THEN** 上传被拒绝，不产生对象，也不以降级模式放行

### Requirement: worker 存储凭据随执行身份注入并回收

worker 获得的存储凭据 MUST 以绑定本次执行身份的 Secret 形式注入，与其凭据值 MUST NOT 出现在 ConfigMap 明文、容器参数、Session Log、事件或任何持久日志；凭据 MUST 随 worker 清理流程一并回收。承载该凭据的 Secret 身份 MUST 进入本次执行的创建意图、启动对账与清理账本，使崩溃后仍可发现并回收。回收失败时清理责任 MUST 保持未决并失败关闭，MUST NOT 报告成功。

#### Scenario: pod 清理回收凭据

- **WHEN** 一次执行尝试结束并触发 worker 清理
- **THEN** 注入的存储凭据 Secret 被列入清理责任并删除，回收失败时保留可重试的清理记录

#### Scenario: 崩溃后仍可发现凭据

- **WHEN** 宿主在创建后崩溃并按创建意图对账
- **THEN** 该 Secret 由意图与对账发现，不成为无主资源

#### Scenario: 凭据不进事件与日志

- **WHEN** 会话事件、遥测与日志记录本次执行的存储活动
- **THEN** 其中只有 ref 与摘要，无任何端点凭据或签名串

### Requirement: 对象保留必须可发现且不静默

对象 MUST 纳入保留账本：超龄或超量的对象 MUST 被标记并呈现给用户裁决。账本 MUST 能发现已上传但未被任何记录引用的对象（列表对账），并计入占用。系统 MUST NOT 静默自动删除对象，也 MUST NOT 在保留总量超限时保持静默。

#### Scenario: 超龄对象被标记

- **WHEN** 某对象超过保留窗口
- **THEN** 它在保留账本中被标记为待裁决并计入占用，不被自动删除

#### Scenario: 无裁决不删除

- **WHEN** 用户未对标记对象作出处置
- **THEN** 对象保持存在，账本持续如实呈现

#### Scenario: 孤儿对象被对账发现

- **WHEN** 某对象已上传但没有任何结果或事件引用它
- **THEN** 列表对账将其纳入账本并标记，不静默留存

### Requirement: 存储后端可插拔且登记为可引用资源

协议层 MUST 只依赖 put/resolve 原语、保留账本所需的列表原语与地址合同，MUST NOT 感知具体后端实现；更换后端不得改变通道载荷与门禁行为。对象存储 MUST 作为可引用资源登记（绑定 schema、凭据引用、统一卡片生命周期），删除仍被引用的存储 MUST 失败关闭，未确认身份的资源 MUST NOT 按可重用名称删除。

引用 MUST 对人类可读：工作台呈现 ref、摘要与校验状态，并提供按 ref 取回内容的显式读取入口；该入口 MUST 走同一解析与绑定约束，MUST NOT 通过生成签名地址暴露内容，MUST NOT 新增对外 HTTP 端点。

#### Scenario: 删除被引用存储失败关闭

- **WHEN** 用户尝试删除仍被执行配置引用的存储资源
- **THEN** 删除被拒绝并给出引用证据

#### Scenario: 后端替换不改合同

- **WHEN** 以另一兼容后端替换对象存储实现
- **THEN** 地址合同、门禁与解析义务行为不变，仅绑定配置不同

#### Scenario: 引用可被人类读取

- **WHEN** 用户在界面上查看一条携带 ref 的记录
- **THEN** 界面呈现 ref、摘要与校验状态，并可经宿主读取入口取回内容，且不产生签名地址

### Requirement: 执行日志全量外置且通道保持有界

作业执行日志的全量内容 MUST 外置到对象存储，回传通道只承载尾部片段与 artifactRef；日志回传 MUST NOT 因全量内容突破有界载荷限制。worker 未完成上传时，宿主可读取 worker 容器日志尾部作为降级取证，该降级 MUST 在载荷中如实标记为非全量，且其上限 MUST 服从运行预算的单一权威上限，MUST NOT 引入与之竞争的第二套硬编码上限。

#### Scenario: 长日志回传为尾部加引用

- **WHEN** 一次执行产生超过通道限额的日志
- **THEN** 通道内只有尾部片段、大小与 ref，全量日志可凭 ref 获取且 hash 可校验

#### Scenario: 降级取证如实标记

- **WHEN** worker 未能上传全量日志，宿主以容器日志尾部取证
- **THEN** 载荷标记该结果为降级且非全量，并在预算上限内，MUST NOT 伪装为全量日志

### Requirement: 会话事件只存地址不存内容

Session Event 与宿主落账 MUST 只记录 artifactRef 与摘要，MUST NOT 记录对象内容本体；外部 worker MUST NOT 直接写 Session Log，artifact 活动的事件由宿主落账。承载 ref 的会话事件 MUST NOT 使会话生产者身份发生不可兼容变化：同一会话内既有的生产者声明 MUST 保持可写，旧读端 MUST 能读取新日志（新增字段对旧读端可忽略）。因承载 ref 而改变投影形状时，投影 MUST 以版本升级表达该变化。

#### Scenario: 事件中只有引用

- **WHEN** 一次外置交接被记录为会话事件
- **THEN** 事件包含 ref、摘要与校验字段，不包含内容本体，也未绕过宿主落账

#### Scenario: 旧读端读取新日志

- **WHEN** 以不识别 ref 字段的旧读端读取包含 ref 的会话日志
- **THEN** 读取成功且不因未知字段失败，日志不因生产者声明冲突变为不可写
