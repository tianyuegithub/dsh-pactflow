# local-execution-workspace Specification

## Purpose

保证本地执行代理在宿主实际沙箱约束内具备写入、构建和提交能力，使真实目录布局不再被临时目录测试掩盖；同时保留历史工作树及失败证据，并以可核对的来源恢复候选改动。

## Requirements

### Requirement: 本地新运行必须具有独立仓库
系统 SHALL 为本地新运行准备包含独立 Git 元数据的任务仓库，不共享主仓可写对象、索引、引用或配置。宿主 MUST 核对基线、分支、远程地址和仓库身份，再按既有合同验证并同步提交。

#### Scenario: 主仓在普通代码目录
- **WHEN** 主仓位于系统临时目录之外且执行代理处于工作区可写模式
- **THEN** 代理可以在任务仓内提交，主仓和其他任务不因此获得附加写权限

### Requirement: 派发前必须验证实际受限执行条件
系统 SHALL 在启动业务子代理前，以对应的沙箱策略和任务目录检查写文件、Git 提交及项目必要工具；缺少策略能力、检查失败或策略在检查后变化 MUST 拒绝执行并给出明确原因，不能以宿主不受限命令通过代替。

#### Scenario: 无法提交
- **WHEN** 实际沙箱拒绝任务 Git 元数据写入
- **THEN** 不启动业务模型，保留失败原因与已创建资源责任

### Requirement: 构建缓存必须位于获准目录
本批次 Maven SHALL 使用任务内私有缓存，不能写入未获宿主支持的共享目录；缓存 MUST 排除于业务提交。用户对共享目录的授权 SHALL 与宿主执行能力分开记录，不能扩张为整个用户目录或全局不受限模式。

#### Scenario: 当前宿主不支持附加目录
- **WHEN** 用户选择先恢复执行
- **THEN** 使用任务内缓存，不宣称共享 ~/.m2 写权限已经生效

### Requirement: 恢复候选必须明确且保留来源
系统 SHALL 只从当前会话、同一需求与节点的终态失败运行读取候选，验证原工作区身份和基线。恢复输入 MUST 显式选择一份候选并绑定内容摘要，参与执行方案授权；摘要漂移、范围不符或基线不符时拒绝。候选只作为未验收输入，执行代理必须重新复核、验证及提交。

#### Scenario: 两份失败现场
- **WHEN** 用户决定恢复已有成果
- **THEN** 可比较候选摘要，新的运行只载入已选候选，旧失败运行不改为成功，原现场不被覆盖或自动删除

### Requirement: 历史解释与清理必须区分仓库类型
新运行 SHALL 持久记录独立仓库类型；缺省类型仅用于解释历史工作树。新载荷 MUST 使用旧版本不能误读的生产者版本。清理独立仓库前必须核对宿主拥有的路径、独立元数据、分支、提交、远程及干净状态，不得按共享工作树删除主仓引用。

#### Scenario: 升级与恢复
- **WHEN** 重载包含旧工作树和新独立仓库的会话
- **THEN** 两者按持久类型读取和清理，旧失败现场继续保留，无法验证的清理失败关闭
