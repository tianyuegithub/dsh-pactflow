# code-input-staleness Specification

## Purpose
让「后序任务实际消费的代码输入」可被追踪与比对：当某依赖在其后序任务运行之后又产生新的成功提交时，该输入必须被**显式报告为过期**；历史事实（后序曾基于哪个提交运行）必须保留，不得静默改写或自动修复。

## Requirements

### Requirement: 后序实际消费的代码输入必须可追踪

运行记录 SHALL 保存该 Run 实际消费的每个代码输入及其来源依赖标识（依赖节点编号）与精确提交。该记录 MUST 可被只读查询。

#### Scenario: 记录包含依赖标识与提交

- **WHEN** 一个声明了代码输入依赖的节点被派发并成功
- **THEN** 该运行的代码输入记录包含每个输入的依赖编号、分支与精确提交

### Requirement: 过期输入必须被显式报告

当某依赖当前的最新成功提交与其在后序运行中记录的提交不同时，只读查询 SHALL 报告该输入过期，并同时给出记录的提交与最新的提交。无法确定依赖最新提交时 MUST NOT 报告过期（不误报）。该查询 MUST NOT 修改任何状态，MUST NOT 自动重跑或自动修复。

#### Scenario: 输入未变时无过期报告

- **WHEN** 每个依赖的最新成功提交与其记录一致
- **THEN** 不报告任何过期输入

#### Scenario: 依赖有新提交时报告过期

- **WHEN** 某依赖的最新成功提交与后序记录的提交不同
- **THEN** 报告该输入过期，并给出 recorded 与 latest

#### Scenario: 未知最新提交不误报

- **WHEN** 某依赖没有已知的成功提交
- **THEN** 不针对该依赖报告过期

#### Scenario: 查询不改变历史

- **WHEN** 报告过期输入
- **THEN** 历史运行记录与其记录的提交保持不变

### Requirement: 过期检测必须在重跑授权路径上真实生效

代码输入过期检测 SHALL 在已成功节点的重跑授权路径上被真实调用，MUST NOT 停留为不可达实现。检测 SHALL 以**重新解析的依赖当前提交**与该节点上次运行记录的提交比对，过期项 MUST 在授权决策点对人可见，且 MUST 至少包含依赖标识、分支、上次记录提交与当前提交四项。

检测结果 MUST NOT 自动决定是否重跑——它是呈现给人的决策依据，不是自动推进的触发条件。检测本身失败或依赖当前提交无法解析时 SHALL 显式报告，MUST NOT 以「无过期项」冒充。

#### Scenario: 检测在重跑授权路径上被调用

- **WHEN** 所有者对一个已成功且依赖上游已变更的节点打开重跑授权
- **THEN** 过期检测被调用并返回该依赖的过期项，四项字段齐备

#### Scenario: 检测不自动触发重跑

- **WHEN** 检测发现存在过期依赖
- **THEN** 不发生任何自动重跑或状态变更，节点仍为 `succeeded`，等待人的决定

#### Scenario: 依赖当前提交不可解析时显式报告

- **WHEN** 某依赖的当前提交无法解析（远端不可达、引用缺失等）
- **THEN** 授权界面显式报告该依赖不可解析，MUST NOT 把它呈现为「未过期」
