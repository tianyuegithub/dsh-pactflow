# run-budgets Specification

## Purpose
约束单次工作的**有限性**：重试次数与输出体积必须有有界预算；预算触及时必须显式说明原因并可被识别，不得静默继续尝试或静默截断降级。

## Requirements

### Requirement: 重试次数必须有界且显式拒绝

Host SHALL 为单个节点的重试设定有界的最大尝试次数。当下一次尝试将超出该预算时，Host MUST 拒绝该重试并给出显式原因（包含实际尝试数与预算值），MUST NOT 继续无限重试。

#### Scenario: 预算内的重试被允许

- **WHEN** 下一次尝试仍在预算内
- **THEN** 重试被接受

#### Scenario: 超出预算的重试被拒绝并说明原因

- **WHEN** 下一次尝试将超出预算
- **THEN** 重试被拒绝，错误信息包含实际尝试数与预算值

### Requirement: 输出体积必须有界且截断可见

Host SHALL 为单个观测的输出/日志文本设定有界的字节预算。文本超出预算时，保留内容 MUST 落在预算内，并 MUST 附带显式截断标记与原始字节数；MUST NOT 静默丢弃超出部分。

#### Scenario: 预算内文本原样保留

- **WHEN** 文本未超出字节预算
- **THEN** 返回原文且标记为未截断

#### Scenario: 超预算文本被有界截断且可见

- **WHEN** 文本超出字节预算
- **THEN** 返回文本落在预算内、标记为已截断、并记录原始字节数

### Requirement: 输出上限必须由运行预算单一权威决定并实际生效

输出/日志文本的字节上限 SHALL 由运行预算的 `maxOutputBytes` 决定，MUST NOT 存在与之竞争的第二套硬编码上限。收紧预算 MUST 实际收紧被保存的输出。截断 MUST 仍是显式且可见的（保留内容落在预算内并带截断标记）。

#### Scenario: 默认预算下超长输出被有界截断

- **WHEN** 输出文本超过默认预算
- **THEN** 保存的文本落在默认预算字节内，并带显式截断标记

#### Scenario: 收紧预算实际收紧输出

- **WHEN** 运行预算的字节上限被收紧到更小值并再次处理同一超长输出
- **THEN** 保存的文本落在收紧后的上限内（预算确实生效，而非被硬编码上限忽略）

### Requirement: 重试预算耗尽必须进入持久暂停而非仅异常拒绝

当节点的重试预算耗尽，宿主 SHALL 将该节点置入**持久暂停状态**（落账、进入投影），而不是仅以异常表达拒绝。暂停节点 MUST NOT 被派发或再次重试（准入对其失败关闭并指名「等待人工恢复」）；恢复 MUST 经由显式的人工动作（`resumeNode`）将节点复位为就绪（依赖仍满足时），且暂停与恢复都 MUST 留下可审计的历史。暂停状态 MUST 可从快照/投影与客户端读出。

#### Scenario: 预算耗尽进入持久暂停

- **WHEN** 对已耗尽重试预算的节点再次触发重试
- **THEN** 节点进入持久暂停状态并落账，后续派发与重试对其失败关闭并指名「等待人工恢复」

#### Scenario: 显式恢复后可再派发

- **WHEN** 人对暂停节点执行显式恢复且其依赖均满足
- **THEN** 节点复位为就绪并可正常派发；暂停与恢复在历史中可审计

#### Scenario: 暂停状态对人与模型可见

- **WHEN** 读取项目快照或打开客户端
- **THEN** 暂停节点以明确的「已暂停（等待决策）」呈现，而非以瞬时失败的形态出现

### Requirement: 文本截断结果不得超过其预算

按字节预算截断文本时，切点 SHALL 落在字符边界上，且结果的字节数 MUST NOT 超过该预算。MUST NOT 产生替代字符（U+FFFD）来代替被切断的字符。

按字节切割后解码会把半个字符替换为三字节的替代字符——比被切断的片段更长，于是「有界」的结果反而超出它本该执行的上限。下游的通道长度断言随即拒绝该负载，抛出的错误替换掉原始失败原因，并使该次运行无法进入终态、其清理也被跳过。本仓库的错误消息大量是中文，这是常见路径而非边角情形。

#### Scenario: 多字节文本的截断结果落在预算内

- **WHEN** 以固定字节预算截断一段长度跨越切点附近若干取值的多字节文本
- **THEN** 每一个取值下的结果字节数都不超过该预算，且结果中不含替代字符

#### Scenario: 预算极小时仍保留截断标记

- **WHEN** 预算小到不足以容纳任何正文
- **THEN** 结果仍然说明自身已被截断

### Requirement: 子进程输出上限与其真实用途相称

Host 执行子进程读取输出时，其输出上限 SHALL 足以容纳该用途的正常输出量。输出溢出 SHALL 与「命令失败」分开表达，MUST NOT 以同一句话呈现。

两者要求的运维动作完全相反。历史查询的输出随仓库历史线性增长，登记的验证命令的输出是整个测试套件的标准输出；上限过低时，收口会报告一个与真因无关的「任务集校验失败」且任何重试都不会成功，而一个通过的测试套件会被报成失败并永久挡住交付。

#### Scenario: 超过一兆字节的历史查询输出可被读取

- **WHEN** 一次 Git 查询产生数兆字节输出
- **THEN** Host 完整读取该输出，不因此失败

#### Scenario: 超过一兆字节的验证命令输出不被判为失败

- **WHEN** 一条登记的验证命令以退出码 0 结束并产生数兆字节标准输出
- **THEN** 该验证被记为通过

#### Scenario: 溢出被指名为溢出

- **WHEN** 子进程输出确实超过了上限
- **THEN** 错误明确指出输出超出上限及其数值，而不是报告命令失败

### Requirement: Harness 墙钟预留按预算比例

为容器内 Harness CLI 计算可用墙钟时，Host SHALL 按该次作业的墙钟预算按比例预留收尾时间，MUST NOT 使用与预算无关的固定值使短预算退化为不可用值。结果 MUST 为正且 MUST NOT 超过该预算。

固定预留只对长预算成立。短预算（探针）下它使可用时间退化为下限值，CLI 必然超时，而用户看到的结论是「模型连接不可用」——一个关于对方系统的判断，成因完全在宿主自己的算术。

#### Scenario: 短预算下 CLI 仍有可用时间

- **WHEN** 以十余秒的墙钟预算创建一次探针作业
- **THEN** 传入 CLI 的可用秒数大于下限值且小于该预算

#### Scenario: 长预算下的预留保持不变

- **WHEN** 以默认的运行墙钟预算创建作业
- **THEN** 预留时间与既有实现一致
