# b-class-impact-list-gate Specification

## Purpose
确保计划 §380 的「B 类执行前给出精确影响清单并取得授权」不只停留在工具层：变更型运行必须先施加清单门禁——清单存在、结构合法、且**授权状态为 granted**（结构有效不等于已授权）；未施加门禁时必须显式可见，不得让一次变更型运行看起来已受约束。

## Requirements

### Requirement: B 类执行必须先有已授权的精确影响清单

变更型（B 类）执行——会改动集群资源或远程分支的运行——SHALL 在开始前施加精确影响清单门禁：清单必须存在、结构合法，且其授权状态 MUST 为 `granted`。结构合法但未授权（`pending`）的清单 MUST 被拒绝，因为「结构有效」不等于「已获授权」。

#### Scenario: 已授权清单通过

- **WHEN** 提供一份结构合法且 `authorization=granted` 的精确影响清单
- **THEN** 门禁通过，运行继续

#### Scenario: 未授权清单被拒绝

- **WHEN** 提供一份结构合法但 `authorization=pending` 的清单
- **THEN** 门禁失败关闭，并指出其未获授权

#### Scenario: 结构非法的清单被拒绝

- **WHEN** 清单缺少必需块、含未知字段、含空数组或枚举非法
- **THEN** 门禁失败关闭并给出结构原因

### Requirement: 未施加影响清单门禁必须显式可见

当变更型运行未提供影响清单时，运行 SHALL 显式声明「本次未施加影响清单门禁」，MUST NOT 静默地让一次变更型运行看起来已受该门禁约束。

#### Scenario: 未提供清单时显式告警

- **WHEN** 变更型运行未提供影响清单
- **THEN** 输出显式告警说明该门禁未被施加，而非静默通过
