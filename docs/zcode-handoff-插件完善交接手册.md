## 2. 插件定位、目标与边界

DSH PactFlow 是 DeepSeek Harness 的外部 Profile Bundle（配置档插件组合包），不是独立聊天平台或第二套网页外壳。目标是在未修改的官方 DSH 上安装、卸载、升级，通过原生界面提供项目、需求、十阶段、DAG（有向无环任务图）、人工评审、执行器、验证和代码收口，并从持久事件恢复。

核心职责关系：用户拥有审批和验证配置 → Host（宿主）负责门禁、调度和可信落账 → Worker（执行器）在独立任务分支执行 → 宿主核验结果、合并与清理 → Client（客户端）展示可重建投影。

- Session Event（会话事件）是领域持久事实；Projection（投影）及其缓存不能成为第二份事实源。
- Remote（远程接口）和智能体工具不能自行授予批准、任意宿主命令或已部署状态。
- K3s 执行结果必须与精确任务、容器组、规格、认领凭据、镜像及代码提交绑定。
- 部署完成与清理完成分开表达，但清理责任必须持久、可发现、可重试。
- 本仓库与 Hermes 版零脉完全独立；禁止读取、理解、复用其源码、数据库、协议或运行时。旧 `data-governance` 不在范围内。
- 不修改 DSH 核心，不使用私有补丁兜底。需要上游通用能力时单独处理，等待受支持发行版。
- 不发布 npm；不删除现有 34 个历史无所有者 Pod（容器组）；不擅自重启用户服务、修改仓库权限或执行真实环境写入。

## 5. 安全停止点：当前明确失败

暂停前最后一个已启动测试已结束，退出码为 1。交接本轮没有重新执行测试；下列结果来自暂停前的实际运行，不是本轮新验证。

```bash
cd /Users/ty/Codes/dsh-pactflow-hardening
pnpm exec vitest run packages/dsh-pactflow/tests/k3s-worker.spec.ts -t 'durable Job binding fails' --maxWorkers=2
```

结果：1 项失败、22 项按名称过滤未运行。`tests/k3s-worker.spec.ts` 的 `does not wait for a result when durable Job binding fails, and still compensates pre-bind resources` 期望删除顺序 `['configmap', 'secret', 'job']`，实际 `[]`。

本轮源码回读确认：`run()` 已取得任务 UID 并设置子资源归属后，先调用 `onBound(jobUid)`，成功后才构造带 UID 的 `boundSpec`。回调失败时仍调用 `cancel(spec)`，传入不带已知 UID 的原规格；`cancel()` 只有收到 UID 才转入 `cleanupRun()` 精确清理，另一分支仍按名称删除。新测试要求每次删除携带精确 UID 条件，旧分支不能满足。

下一安全修复候选：在回调前保留已知任务身份，失败补偿使用该身份；保持不进入结果等待、原始绑定错误不被清理错误掩盖，并证明清理失败可持久追踪。**尚未实施此修复。** 更早的密钥/配置映射/任务创建失败、归属绑定失败、创建响应不明等分支不能靠这一处调整自动解决，必须分别取证。

不要删除测试、弱化 UID 断言或只让删除数组符合预期。测试中使用隔离 Kubernetes 接口替身，未删除真实资源。
